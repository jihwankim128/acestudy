# toss-note — Toss 학습 노트 정리

Claude Code(`/toss-note`)와 Codex(`$toss-note`)가 함께 쓴다. `AGENTS.md` 의 페르소나로 정리한다.
노트는 `toss-notes/<github-id>/` 에 쌓이고, main에 머지되면 사이트 `/toss-notes/#/<github-id>` 에 그대로 보인다.

**목표는 예쁜 요약이 아니라 "어디서 틀렸고 지금은 어떻게 이해하는가"를 남기는 것이다.**
교과서 정리는 쓰지 않는다. 학습자가 실제로 쓴 답과 교정 과정이 노트의 본체다.

## 1. 준비
```bash
gh api user -q .login                       # 내 GitHub 아이디
git switch main && git pull
ls "toss-notes/<아이디>/"                    # 내 노트 폴더
```
- 다른 팀원의 폴더는 읽기만 한다. 수정하지 않는다.
- `toss-notes/<아이디>/00 학습 지도.md` 가 **없으면 처음 사용**이다 → 2번부터.
- 있지만 "학습 범위" 표가 없으면(예전 형식) 이번이 이 스킬의 첫 사용이다 → 2번의 1~3을 하고, 기존 진행 상황을 "학습 범위" 표로 옮긴다.
- 있으면 학습 지도와 기존 노트를 읽고 3번으로 간다.

## 2. 처음 사용: 학습할 주제를 먼저 정한다
노트를 쓰기 전에 학습 범위를 명시해야 한다. 범위가 없으면 노트가 흩어지고, 무엇이 끝났는지 알 수 없다.

1. 이 스킬이 하는 일을 세 줄로 알려준다.
   - 학습한 내용 중 노트가 필요한 것만 골라 개념 하나에 노트 하나로 정리한다.
   - 학습 지도(`00 학습 지도.md`)에 진행 상황, 반복하는 실수, 열린 질문을 쌓는다.
   - 정리가 끝나면 PR을 올리고, 머지되면 사이트 Toss 노트 탭에 보인다.
2. 문제은행을 주제로 묶어 보여준다. 문항 목록은 `site/toss/questions.js` 에서 읽는다.
   ```bash
   node -e "import('./site/toss/questions.js').then(m=>{for(const k of ['CODING','CONCEPT','QUIZ','DESIGN'])for(const x of m[k])console.log(x.id,(x.title||x.q).replace(/<[^>]+>/g,'').slice(0,50))})"
   ```
   아래는 현재 문제은행 기준의 묶음 예시다. `questions.js` 와 다르면 `questions.js` 를 따른다.

   | 주제 | 관련 문항 |
   |---|---|
   | 동시성과 정합성 (락, 격리수준, 데드락) | s1 s7 s16 k2 k3 k4 k5 k17 d7 |
   | 멱등성과 결과를 모르는 요청 | c2 s6 k1 d1 |
   | 메시징 (Kafka 순서, 오프셋, Outbox, CDC) | s3 s4 s5 s17 k8~k12 k28 d2 |
   | 처리량과 외부 연동 (Little's Law, 유량 제어, 서킷 브레이커) | c4 s15 k13~k16 k26 k27 |
   | DB 인덱스와 쿼리 | s2 k6 k7 |
   | 네트워크 (TIME_WAIT, 포트) | s8 k18 k19 |
   | 실시간 전송과 알림 (polling, SSE, 목표가 알림) | s12 k24 d3 d10 |
   | 캐시 (스탬피드, 시세 캐시) | s9 k20 d9 |
   | 데이터 모델과 일관성 (금액 계산, CQRS, 대사) | s10 s11 k21~k23 d5 d6 d8 |
   | 운영과 성능 (JVM 메모리, p99, 장애 대응) | s13 s14 k25 d4 |
   | 코딩 (매칭 엔진, 캔들, 기동 순서, 정렬·힙) | c1 c3 c5 k29 k30 |

3. 학습자에게 묻는다. **답을 대신 정하지 않는다.**
   - 이번 시험(또는 이번 주)까지 학습할 주제는 무엇인가. 위 묶음에서 고르거나 직접 쓴다.
   - 주제마다 지금 자신감은 어떤가. (모름 / 들어봄 / 설명 가능)
   - 시험 날짜나 마감이 있는가.
4. 답을 받아 `toss-notes/<아이디>/00 학습 지도.md` 를 만든다. 형식은 아래 "학습 지도 형식".
   - 고른 주제는 진행 상황 표에 모두 `대기` 로 넣는다. 아직 학습하지 않은 주제의 노트는 만들지 않는다.
   - 학습자가 이미 학습한 내용을 가져왔다면 이어서 3번으로 간다.

## 3. 노트가 필요한지 판단한다
학습 내용(이 대화, 붙여 넣은 GPT 대화, 학습자의 설명)을 읽고 항목마다 판단한다.

| 상황 | 할 일 |
|---|---|
| 처음 쓴 답이 틀렸거나 반쯤 맞았고, 교정됐다 | **새 노트** (또는 같은 개념 노트에 추가) |
| 새 개념을 배웠고, 학습자가 자기 말로 다시 설명했다 | **새 노트** |
| 기존 노트의 열린 질문에 답했다 | **기존 노트 갱신** (답과 판정 기록) |
| 같은 실수가 두 번째로 나왔다 | 학습 지도 "반복하는 실수"에 추가 |
| 처음부터 정확히 답한 단순 암기 (키워드 문항 등) | 노트 없이 학습 지도 상태만 갱신 |
| 학습 범위 밖의 곁가지 | 노트 없이 학습 지도 "열린 질문"이나 다음 주제 후보로 |

판단 결과를 학습자에게 먼저 보여주고 확정한다. 예: "새 노트 1개(결과를 모르는 요청), 기존 노트 갱신 1개, 학습 지도 상태 2곳 변경".
학습 내용이 아직 없으면 노트를 지어내지 않는다. 학습을 먼저 하자고 말한다.

## 4. 노트 쓰기 — `toss-notes/<아이디>/<개념 이름>.md`
- **개념 하나 = 노트 하나.** 파일 이름이 곧 `[[링크]]` 이름이다. 문항 번호가 아니라 개념으로 짓는다. (예: `결과를 모르는 요청.md`)
- 같은 개념의 노트가 이미 있으면 새로 만들지 않고 그 노트에 추가한다.
- 하위 폴더를 만들면 사이트 트리에서 그룹으로 묶인다. 노트가 10개를 넘기 전까지는 폴더 없이 둔다.

```markdown
---
date: 2026-10-29
tags: [정합성, 멱등성]
---
## 핵심 한 줄
**한 문장으로 이 개념의 본질.**

## 장면
(실제 장애나 상황. 흐름이 있으면 mermaid)

## 내 첫 답
> [!quote] 9번 — (문항 요약)
> 학습자가 처음 쓴 답 그대로.

## 틀린 지점
> [!failure] 틀린 주장 한 줄
> 왜 틀렸는지. 무엇이 기준이었어야 했는지.

## 교정된 이해
- 지금 다시 설명하면. 숫자와 서버에서 일어나는 일로 끝낸다.

## 열린 질문
> [!question]- 아직 못 푼 질문
> (아직 안 풀었음)

## 연결
- [[다른 노트]]: 왜 연결되는지 한 줄
- [[c2]]: 관련 문항
- [[net.timeout-retry]]: 관련 CS 스터디 토픽
```

**규칙**
- **내 첫 답은 고치지 않는다.** 오타 정도만 둔다. 나중에 다시 답하면 아래에 `> [!quote] 다시 쓴 답 (날짜)` 로 추가한다.
- **틀린 지점이 제일 중요하다.** "몰랐다"가 아니라 어떤 잘못된 기준으로 생각했는지 쓴다.
- **열린 질문에 답을 쓰지 않는다.** 힌트도 붙이지 않는다. 학습자가 풀면 그때 그 답과 판정(맞음 / 부분 / 틀림 + 이유)을 기록하고 `[!question]-` 을 `[!success]-` 로 바꾼다.
- 교정된 이해는 학습자가 실제로 이해한 수준까지만 쓴다. 대화에서 다루지 않은 내용을 덧붙이지 않는다.
- 확실하지 않거나 구현마다 다른 내용은 그렇다고 쓴다. (예: InnoDB 기준, Kafka 3.x 기준)
- 링크 대상: 같은 팀원의 노트 이름, 문항 id(`c1`, `s4`, `k13`, `d1`), CS 스터디 토픽 id(`os.thread`, `curriculum/topics.yaml`). 링크마다 이유를 한 줄 쓴다.

**사이트가 보여 주는 옵시디언 문법**
- `[[노트]]`, `[[노트|보일 이름]]`, `![[그림.png]]`, `> [!type]` 콜아웃(`+`/`-` 로 접기), `==강조==`, ` ```mermaid `
- 콜아웃 종류: quote, failure, warning, success, question, note, tip
- mermaid 라벨에 `#` 을 쓰지 않는다 (잘린다). 그림은 내 폴더에 두고 1MB 이하.

## 5. 학습 지도 갱신 — `00 학습 지도.md`
노트를 쓰거나 고칠 때마다 함께 갱신한다.

**학습 지도 형식**
```markdown
---
date: 2026-10-29
tags: [지도]
---
토스증권 서버 필기 대비 학습 기록. 시험: 2026-11-xx

## 학습 범위
| 주제 | 관련 문항 | 노트 | 상태 |
|---|---|---|---|
| 처리량과 외부 연동 | [[c4]] [[s15]] | [[처리량과 큐 적체]] | 통과 |
| 멱등성과 결과를 모르는 요청 | [[c2]] [[s6]] | [[결과를 모르는 요청]] | ==핵심 미완== |
| 메시징 | [[s4]] [[k10]] | | 대기 |

## 내가 반복하는 실수
> [!warning] 1. 실수 이름
> 어떤 모습으로 나왔는지, 다음엔 어떻게 쓸지. → [[관련 노트]]

## 열린 질문
- [ ] 아직 못 푼 질문 (답하면 해당 노트에 기록)
```

- 상태: `대기` → `진행` → `==핵심 미완==` → `통과`
  - `통과`: 교정된 이해를 학습자가 자기 말로 다시 설명했고, 관련 문항 답안이 핵심을 짚었다.
  - `==핵심 미완==`: 학습은 했지만 핵심 질문이 열려 있다.
- 학습 범위를 바꾸고 싶다고 하면 표에 주제를 더하거나 뺀다. 뺀 주제의 노트는 지우지 않는다.
- 열린 질문을 풀면 체크(`- [x]`)하고 해당 노트에 기록한다.

## 6. 확인과 PR
```bash
npm run check
npm run dev    # http://localhost:8787/toss-notes/#/<아이디> 에서 확인
```
- 링크가 회색(해결 안 됨)으로 보이면 노트 이름이나 문항 id 오타다.
- 콜아웃, mermaid가 의도대로 보이는지 본다.

학습 노트는 하나씩 PR로 올린다.
```bash
git switch -c toss-note/<아이디>-<짧은-영문-slug>
git add "toss-notes/<아이디>/"
git commit -m "toss-note(<아이디>): <한 줄 요약>"
git push -u origin HEAD
gh pr create --base main --title "toss-note(<아이디>): <한 줄 요약>" --body "<새 노트, 갱신한 노트, 학습 지도 변경>"
```
- 머지되면 Vercel이 다시 빌드해서 사이트에 반영된다.
- 마지막에 학습자에게 열린 질문 중 다음에 풀 것 하나를 고르게 한다. 답은 주지 않는다.
