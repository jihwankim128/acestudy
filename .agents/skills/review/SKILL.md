# review — 팀원 학습 PR 리뷰

Claude Code(`/review`)와 Codex(`$review`)가 함께 쓴다. `AGENTS.md` 의 페르소나로 리뷰한다. 날카롭게 보되 목적은 서로 더 깊이 배우는 것이다.

## 1. 대상 고르기
```bash
gh pr list --search "study( in:title" --state open
gh pr checkout <번호>
npm run check
```
- 내가 작성한 PR은 리뷰하지 않는다.

## 2. 사용자와 함께 읽기 (5~10분)
- 노트를 요약해서 보여주고, 사용자에게 핵심 질문 1개를 먼저 던진다. 리뷰어도 이 시간에 그 토픽을 배운다.
- `npm run dev` → `http://localhost:8787/#/topic/<topic-id>` 에서 시각화가 의도대로 동작하는지 확인한다.

## 3. 검토 기준
| 항목 | 확인 |
|---|---|
| 정확성 | 사실 오류, 오래된 정보, 구현과 버전에 따라 다른데 일반화한 서술 |
| 깊이 | 제1원리("왜 이렇게 만들었나")가 있는가. 백엔드 실전 사례로 착지하는가 |
| 링크 | `prerequisites` / `leads_to` 방향이 맞는가. 빠진 핵심 링크나 억지 링크가 없는가. `npm run context` 의 기존 노트와 모순이 없는가 |
| 시각화 | 핵심 동작을 단계별로 보여주는가. 다크/라이트 모드에서 모두 보이는가 |
| 퀴즈 | 모범답안이 정확한가. 면접 수준 질문이 있는가 |
| 제안 | `suggest` 가 정말 별도 토픽감인가. 이미 있는 토픽과 겹치지 않는가 |

## 4. 리뷰 남기기
- 수정이 필요한 건 해당 줄에 근거와 함께 남긴다.
- 작성자에게 **질문 1개**를 꼭 남긴다. 노트를 한 단계 더 깊게 만들 질문으로.
- 사용자에게 리뷰 내용을 보여주고 확인받은 뒤 등록한다.
```bash
gh pr review <번호> --comment --body "<리뷰>"       # 의견
gh pr review <번호> --approve --body "<리뷰>"       # 문제 없음
gh pr review <번호> --request-changes --body "<리뷰>"   # 사실 오류가 있을 때만
```
