토스증권 서버 필기

코딩 1주관식 5 (25분)서술형 2 (30분) 문제은행 문항
공개 기출과 토스증권 기술 글로 만든 문제를 풀고, 팀원의 답안과 나란히 비교합니다. 왼쪽 목록에서 문항을 고르세요.

무엇이 나올까

토스증권의 이번 시험 문항은 공개되지 않았습니다. 아래 확인은 출처가 있는 사실, 추정은 그 사실에서 끌어낸 제 예측입니다.

코딩 테스트

  • 확인 토스 서버 직군 코테는 고난도 알고리즘보다 요구사항을 정확히 읽고 구현하는 문제가 중심이라는 후기가 반복됩니다. 2021년은 6문제/2시간, 2022년은 7문제/90분.
  • 확인 2022년 후기 기준 유형: 문자열·반복 구현, 값 범위가 커서 압축이 필요한 문제, map/set 활용, 마지막 1문제만 골드5 수준.
  • 확인 공개 기출: 멋쟁이 숫자(서버 직군, 문자열+반복), Lockfile을 만들어보자(의존성 그래프 재귀 탐색, 결정적 버전 선택).
  • 추정 이번엔 1문제뿐이라 증권 도메인 시나리오를 그대로 구현하는 중간 난이도일 가능성이 큽니다. 주문 매칭, 원장 반영, 시세 집계, 유량 제어처럼 자료구조 선택(우선순위 큐, 해시맵, 덱)이 핵심인 형태.

주관식·서술형

  • 확인 과거 서버 직군 서술형은 30분에 5~6문항, 문항당 약 5분. 검색 없이 아는 지식으로 답하게 설계됐고, 대용량 트래픽 시스템이나 신뢰도 있는 상품을 만드는 실무 상황을 물었다는 후기가 있습니다.
  • 확인 토스증권 공식 글이 직접 강조하는 주제: 정합성과 트랜잭션, CQRS 읽기 뷰와 검증, 모니터링, 장애 트러블슈팅 순서, 통합 레이어.
  • 확인 이번 시험 안내: 주관식 5문항 25분, 서술형 2문항 30분. 문항당 주관식 5분, 서술형 15분입니다.
  • 추정 주관식 5분은 과거 서버 직군 서술형(30분에 5~6문항)과 같은 분량입니다. 그래서 용어 한 단어보다 결론 한 줄과 근거 1~2문장의 짧은 서술이 중심일 가능성이 큽니다. 용어·숫자로 끝나는 문항이 섞일 수 있어 키워드 문항도 둡니다.
  • 추정 서술형 15분은 설계·장애 대응형입니다. CS 개념을 서버 장애 장면으로 비틀거나, 토스증권이 실제로 겪은 문제(브로커 지연, 시세 fan-out, 원장 정합성)를 설계 문제로 낼 것으로 봅니다.

토스증권이 공개한 기술 소재

해외주식 서비스 안정화 (toss.tech)미국 정규장 개장 직후 TPS가 비정규장의 20배 이상. 예약주문 약 100만 건을 브로커 TPS 상한 이하로 보내려 resilience4j RateLimiter 사용, TPS는 배치 파라미터로 주입. 1분 실패 수 임계치로 이상 감지 → 서브 브로커로 자동 failover. 원천은 Oracle 날짜 파티션, 계좌 조회용은 MongoDB.서술형 1, 주관식 6·15, 키워드 13·26
서버 챕터 FAQ (토스 커리어)원본 Oracle + 읽기 뷰 분리(CQRS), Vitess(MySQL 샤딩)로 수평 확장, p95 약 40ms. 읽기 뷰는 실시간 검증기와 매일 잔차 배치로 오염 확인. 모니터링 지표는 에러 수, 스레드 고갈, API 실패율, Kafka lag. 장애 시 변경 이력 → 분산 추적(Jaeger, Pinpoint) → tcpdump·thread dump.서술형 4·5·8, 주관식 11·14, 키워드 23
Kafka 이중화 #3 (toss.tech)Active-Active 클러스터 간 consumer offset 동기화. 재난 시 유실은 절대 불가, 중복은 최소화. MM2의 보수적 offset 변환, timestamp 기반 offset 검색.주관식 4·17, 키워드 28
SLASH 발표토스증권 실시간 시세 적용기(22), 애플 한 주가 고객에게 전달되기까지: 주문 동시성·브로커 장애 격리(22), 실시간 시세 데이터 안전하고 빠르게 처리하기(23), SSE 이벤트 푸쉬로 Polling 제거(24), 리플레이 검증으로 새 금융 시스템 도입(24), ClickHouse 랭킹(24).서술형 2·3·6·7, 주관식 12, 키워드 24

답안 쓰는 틀

주관식 · 키워드형이 나오면

  • 정식 용어로 씁니다. 한글과 영문이 둘 다 있으면 같이 적습니다. 예: 멱등성(idempotency).
  • 계산 문항은 단위까지 씁니다. 300개, 500초.
  • 출력 예측은 한 번 더 의심합니다. equals와 compareTo, 정수 나눗셈, 오버플로.
  • 모르면 비워 두지 말고 가장 가까운 개념이라도 씁니다.

주관식 · 서술 (문항당 5분)

  • 첫 문장이 결론입니다. 묻는 말에 바로 답합니다.
  • 근거는 1~2문장. 메커니즘을 한 단계 아래 계층으로 설명합니다 (DB면 락·MVCC, 네트워크면 TCP 상태).
  • 대응책이나 해결책을 하나 이상, 이름과 함께 씁니다.
  • 숫자가 있으면 계산을 보여 줍니다. 예: 100 req/s × 3s = 동시 300. 각 문항의 "5분 답안"이 이 분량의 기준입니다.

서술형 · 설계 (문항당 15분)

  • 무엇이 깨지면 안 되는지부터 정의합니다. 증권은 거의 항상 유실 없음, 중복 없음, 잔고 정합성.
  • 숫자로 병목을 찾습니다. TPS, 지연, 건수.
  • 구조 → 실패 시나리오(타임아웃, 중복, 순서 역전, 부분 장애) → 트레이드오프 순서로 씁니다.
  • 마지막에 관측과 검증: 어떤 지표로 알아채고, 어떻게 대사(reconciliation)할지.
