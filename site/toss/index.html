무엇이 나올까

토스증권의 이번 시험 문항은 공개되지 않았습니다. 아래 확인은 출처가 있는 사실, 추정은 그 사실에서 끌어낸 제 예측입니다.

코딩 테스트

  • 확인 토스 서버 직군 코테는 고난도 알고리즘보다 요구사항을 정확히 읽고 구현하는 문제가 중심이라는 후기가 반복됩니다. 2021년은 6문제/2시간, 2022년은 7문제/90분.
  • 확인 2022년 후기 기준 유형: 문자열·반복 구현, 값 범위가 커서 압축이 필요한 문제, map/set 활용, 마지막 1문제만 골드5 수준.
  • 확인 공개 기출: 멋쟁이 숫자(서버 직군, 문자열+반복), Lockfile을 만들어보자(의존성 그래프 재귀 탐색, 결정적 버전 선택).
  • 추정 이번엔 1문제뿐이라 증권 도메인 시나리오를 그대로 구현하는 중간 난이도일 가능성이 큽니다. 주문 매칭, 원장 반영, 시세 집계, 유량 제어처럼 자료구조 선택(우선순위 큐, 해시맵, 덱)이 핵심인 형태.

주관식·서술형

  • 확인 과거 서버 직군 서술형은 30분에 5~6문항, 문항당 약 5분. 검색 없이 아는 지식으로 답하게 설계됐고, 대용량 트래픽 시스템이나 신뢰도 있는 상품을 만드는 실무 상황을 물었다는 후기가 있습니다.
  • 확인 토스증권 공식 글이 직접 강조하는 주제: 정합성과 트랜잭션, CQRS 읽기 뷰와 검증, 모니터링, 장애 트러블슈팅 순서, 통합 레이어.
  • 추정 시험 구성에 주관식 5와 서술형 2가 따로 적혀 있으므로, 주관식은 답이 하나로 정해진 단답형(용어, 빈칸, 계산, 출력 예측)일 가능성이 높습니다. 토스가 형식을 공개한 적은 없어서, 2~3문장 짧은 서술로 나올 경우에 대비해 서술형 탭에 개념 서술 문항을 함께 두었습니다.
  • 추정 서술형은 CS 개념(격리수준, 인덱스, TCP, 스레드, GC)을 서버 장애 장면으로 비틀거나, 토스증권이 실제로 겪은 문제(브로커 지연, 시세 fan-out, 원장 정합성)를 설계 문제로 낼 것으로 봅니다.

답안 쓰는 틀

주관식 · 단답형

  • 정식 용어로 씁니다. 한글과 영문이 둘 다 있으면 같이 적습니다. 예: 멱등성(idempotency).
  • 계산 문항은 단위까지 씁니다. 300개, 500초.
  • 출력 예측은 한 번 더 의심합니다. equals와 compareTo, 정수 나눗셈, 오버플로.
  • 모르면 비워 두지 말고 가장 가까운 개념이라도 씁니다.

서술형 · 개념 (문항당 5분 안팎)

  • 첫 줄에 결론 한 문장.
  • 왜 그런지 메커니즘을 한 단계 아래 계층으로 설명 (DB면 락·MVCC, 네트워크면 TCP 상태).
  • 대응책은 두 개 이상, 각각의 비용을 한 마디씩.
  • 숫자가 있으면 계산을 보여 줍니다. 예: 100 req/s × 3s = 동시 300.

서술형 · 설계 (문항당 15분 안팎)

  • 무엇이 깨지면 안 되는지부터 정의합니다. 증권은 거의 항상 유실 없음, 중복 없음, 잔고 정합성.
  • 숫자로 병목을 찾습니다. TPS, 지연, 건수.
  • 구조 → 실패 시나리오(타임아웃, 중복, 순서 역전, 부분 장애) → 트레이드오프 순서로 씁니다.
  • 마지막에 관측과 검증: 어떤 지표로 알아채고, 어떻게 대사(reconciliation)할지.
